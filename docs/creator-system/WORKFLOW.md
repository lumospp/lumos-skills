# Workflow — 从模糊种子 / 真实问题到公开内容

## 总览

Creator System 支持两种入口：

```text
Problem-first
Capture → Select → Frame → Research → Judge → Red Team → Draft → Publish → Learn

Seed-first
Capture → Incubate（可选）→ Crystallize → Select → Frame → Research → Judge → Red Team → Draft → Publish → Learn
```

平台适配属于 Draft 与 Publish 之间的可选子步骤。

**Incubate 不是新的必经阶段。** 只有当输入还是概念、感受、片段、半成品念头，用户又不知道该问什么时才启用。

每一步都有退出条件。达到退出条件就继续，不因为还能做得更好而无限停留。

Modern Thinking Tools 是 Frame / Research / Judge / Red Team / Learn 的默认推理底座；Seed 还没成形时不强行运行完整模型路由。

---

## 0. Capture — 捕捉，不处理

### 输入

任何让你多停留了一秒的东西都可以：

- “奇怪，为什么会这样？”
- “这和大家通常说的不一样。”
- “刚学了一个概念，感觉挺有意思。”
- “跟人聊了一句，好像有点东西。”
- “这个想法还很模糊，但我想记下来。”

### 动作

最小记录：

```text
原话 / 种子：
来源：自己 / 用户 / 评论 / 平台 / 学习 / 工作 / 对话
```

如果能顺手写出“我觉得有意思的地方”，就写；写不出来完全没关系。

不要立刻研究，也不要要求自己先想出问题。

### 退出条件

**30 秒内记完。**

---

## 0.5 Incubate — 对话孵化（可选）

### 什么时候启用

当出现这些情况：

- “我不知道该问什么。”
- “就是觉得这个概念有意思。”
- “脑子里有一点东西，但说不清。”
- “我想先聊聊。”
- 很多观点是在和人 / AI 的对话中逐渐出现。

### 目标

不是马上得到“正确问题”，而是让材料长出来：

```text
Seed
 ↓
真实反应
 ↓
连接 / 对比 / 案例
 ↓
张力逐渐显形
 ↓
候选问题 / 候选判断
```

### AI 默认循环

```text
接住 → 展开 → 连接 → 轻问
```

#### 接住

准确复述用户正在在意的点，允许用户说“不是，我想表达的是……”。

#### 展开

每轮最多主动增加 1~2 个高信息量材料：

- 一个现实场景；
- 一个对比；
- 一个反例；
- 一个相关概念；
- 一个可能与用户经历相连的方向。

这些只是候选，不冒充用户观点。

#### 连接

优先把 Seed 连到：

- 用户真实经历；
- 工作 / 学习 / 产品 Case；
- 已经讨论过的问题；
- 一个能产生现实反馈的场景。

#### 轻问

一次最多问 **1 个**高信息价值问题。

优先：

```text
你第一次想到的是哪件具体事？
这里最让你意外的是哪一点？
A / B 哪个更接近你的感觉？
```

避免：

```text
你的核心问题是什么？
你真正想表达什么？
请给出你的初始理论。
```

如果用户说“不知道 / 脑子空白”，AI 应给 2~3 个具体方向，让用户只需要选“哪个有感觉 / 都不对”。

### Crystallize — 结晶

当出现以下任意 2~3 个信号时，AI 主动结晶：

- 一个反复出现的张力；
- 一个具体 Case；
- 用户明显认可的一句话；
- 一个可解释机制；
- 一个外部读者也会遇到的问题；
- 用户说“这个可以写 / 帮我整理”。

输出：

```text
真正聊出来的主题：
你似乎最在意的点：
核心张力：
候选真问题（1~3 个）：
候选核心判断（如有）：
已有案例 / 材料：
AI 提出但你尚未确认的内容：
需要外部查证：
只有你能补充：
```

### 退出条件

不要求“已经想清楚”。只要满足之一即可：

- 已有一个值得进一步研究的问题；
- 已有一个值得继续验证的候选判断；
- 已经确认这个 Seed 暂时只是一条连接，不需要继续。

详细协议见 `INCUBATION.md`。

## 1. Select — 选一个值得现在继续的方向

对于清楚问题，直接选择问题。

对于 Seed-first，对 Crystallize 产生的 1~3 个方向做轻量选择。

只看：

1. 真实性：是否来自真实注意 / 经历 / 对话？
2. 张力：有没有值得多想一步的冲突？
3. 解释空间：是不是还存在一个没讲清的机制？
4. 长期相关：是否和长期关心的主题产生连接？
5. 可完成性：当前投入能不能形成一个阶段性判断？

不要求精细打分；也不要因为刚学了某个模型就优先选它。

### 退出条件

选择 **1 个**继续推进的方向，其他放回 Seed / Problem Pool。

---

## 2. Frame — 压成一句真问题

这一步由 AI 和人共同完成，不要求用户从空白页独立完成。

优先形式：

```text
为什么明明 X，却 Y？
为什么大家通常认为 X，但现实里出现 Y？
什么情况下 X 有效，什么情况下反而有害？
真正决定 X 的变量是什么？
```

检查：

- 是否包含可观察现象？
- 是否一篇内容能回答？
- 是否偷偷预设结论？
- 是否把价值判断伪装成事实？

### Modern Thinking 最小问题地图

对非平凡问题按需检查：

```text
目标：要解释 / 判断 / 选择什么？
时间尺度：一次事件还是长期机制？
关键未知：什么事实最可能改变当前判断？
硬约束：有哪些边界不能靠意愿绕开？
失败方式：最可能把题立错在哪里？
```

### 退出条件

能用一句话表达当前真问题，且知道什么未知最可能改变题目。

---

## 3. Research — 研究，不急着证明自己

### 3.1 先列竞争解释

```text
H1：常见解释
H2：当前怀疑的解释
H3：竞争解释 / 更简单解释
```

Modern Thinking 可以生成机制不同的候选解释，但它们只是待检验假说。

### 3.2 研究强度

**Light**：个人观察、低风险观点、已有成熟知识。

**Standard**：学习科学、因果、数据、社会现象等需要可靠证据，调用 `research`。

**Deep**：争议大、影响大、准备形成长期方法，再加 `evidence-audit`。

### 3.3 Thinking 与 Evidence 分工

> **Thinking 生成问题、机制与竞争假说；Research / Evidence Audit 查事实和证据。**

```text
真问题
 ↓
Thinking：候选机制 / 关键未知 / 区分性预测
 ↓
Research：事实 / 研究 / 数据 / 参考类 / 反例
 ↓
Judge
```

禁止让思维模型本身充当证据。

### 3.4 停止规则

每查一轮问：

> 哪个未知如果查清楚，最可能改变当前判断？

新增信息只是在重复支持已有观点时停止。

### 退出条件

能说清：

- 当前最可信解释；
- 最大竞争解释；
- 最大反例 / 边界；
- 哪些仍未知；
- 什么新证据最可能改变排序。

---

## 4. Judge — 人拥有判断，AI 帮助结晶

这是 Modern Thinking Tools 的主要工位。

### 4.1 AI 推理路由

对非平凡问题：

1. 选 1 个主工具；
2. 最多 3 个补充 / 反证工具；
3. 每个工具承担明确工位；
4. 删除后结论不变的工具不要用；
5. 模型与证据冲突，以证据和现实为准；
6. 输出关键机制、权衡、行动含义和更新条件。

### 4.2 判断所有权

如果用户已经在对话中形成了明显倾向，AI 可以从其表达中提炼 1~3 个候选判断，让用户确认 / 修正。

不再机械要求用户从空白页写四句话。

真正需要确认的是：

```text
这是我当前认可的判断：
我知道最关键依据：
我知道它在哪些情况下不适用：
我知道什么证据会让我改变判断：
```

### 退出条件

用户能确认并用自己的话解释文章主线。

如果只是“这句话看起来很有道理”，但自己讲不出来，返回 Incubate / Research / Judge。

---

## 5. Red Team — 判断先过攻击，再进入写作

固定检查：

- 有没有更简单解释？
- 有没有基准率 / 参考类问题？
- 有没有选择偏差？
- 有没有把相关当因果？
- 有没有个人经验外推过度？
- 有没有尾部风险或不可逆损失？
- 有没有代理指标 / 古德哈特问题？
- 有没有二阶反应或适应性行为？
- 证据真正允许结论说到多强？

如果 Judge 已有主工具，优先用不同类型的异质工具攻击，而不是同类模型互相确认。

### 退出条件

- 判断仍成立；或
- 已降级到证据真正支持的强度；或
- 发现题立错，退回 Frame / Research。

---

## 6. Draft — 从“已有材料”写，不从空白页重新开始

### 用户明确说“整理成文章”时

把此前对话视为主要材料，不重新要求用户填一遍流程。

AI 先内部完成 Article Brief：

```text
真正主题：
用户已经认可的核心判断：
关键推理链：
用户自己的案例 / 措辞 / 转折：
AI 提出但尚未确认：
需要外部查证：
只有用户能补充：
```

然后做 Gap Check：

- 外部事实、论文、定义、数据 → AI 自己 Research；
- 只有用户本人知道、且会改变文章 → 问 1~3 个具体问题；
- 小细节缺失 → 保守处理、删除或标明不确定。

### 母稿纪律

- 一篇一个核心判断；
- 每段服务主线；
- 术语能不出现就不出现；
- 案例优先于概念，机制优先于模型名；
- 尽量保留用户真实表达和思路演化；
- 删除正确但不必要的内容；
- 不制造假共识、金句和宏大升华；
- Judge 用过的模型不代表必须写进文章。

### 退出条件

母稿能独立成立，用户愿意为核心判断负责。

如果材料只够 L1 / L2，就不硬凑 L3 长文。

---

## 7. Adapt — 平台适配

先有母稿，再适配。

只改：

1. 入口；
2. 信息密度；
3. 表达媒介。

一次内容最多适配 2 个平台。

传播表达可以更锋利，但**事实边界和核心判断不能比母稿更宽**。

---

## 8. Publish — 发布就是实验

发布前检查：

- 核心判断是否清楚？
- 标题是否对应真实问题？
- 是否有明显事实错误？
- 是否把推断写成事实？
- 是否为了完整加入过多支线？

然后发布，不无限润色。

---

## 9. Learn — 反馈不是只看点赞

24~72 小时后记录：

### 内容反馈

- 哪句话被反复引用 / 评论？
- 大家误解在哪里？
- 有什么强反驳？
- 有没有新案例 / 反例？
- 有没有长出新 Seed / 新问题？

### 数据反馈

只选 2~3 个指标：点击 / 打开、完读 / 停留、收藏 / 转发、评论 / 私信。

不要用单一指标代表内容质量。

### 判断反馈

对照发布前 Update Condition：

```text
新信息只是传播反馈？
修正量级？
修正边界？
还是足以推翻核心机制？
```

### 自己的反馈

- 写完以后，我对问题的理解改变了吗？
- 哪个工具真正改变判断？哪个只是标签？
- AI 在哪里降低了压力？
- AI 在哪里替我想过头了？
- 哪一步最卡 / 多余？

### 写回知识库

真正有效的模型使用经验才写回 Model Card；新的模糊连接可以进入 Seed Pool，不强迫立刻分配 Problem ID。

### 退出条件

至少得到一项：

- 判断更新；
- 新问题；
- 新 Seed；
- 流程改进；
- 值得写回 Model Card 的新理解。

然后关闭这一轮。
