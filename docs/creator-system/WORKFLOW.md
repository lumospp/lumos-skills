# Workflow — Creator System V0.3

> 用户只需要感知六个阶段；内部需要时再展开成 Incubate / Frame / Research / Judge / Red Team / Draft / Adapt / Publish。

## 总览

```text
1. CAPTURE
   ↓
2. CRYSTALLIZE
   ↓
3. THINK
   ↓
4. JUDGE
   ↓
5. CREATE
   ↓
6. LEARN
   ↺
```

两种入口：

```text
Problem-first
清楚问题 → CRYSTALLIZE / THINK

Seed-first
一句话 / 概念 / 感受
→ progressive-elaboration
→ CRYSTALLIZE
```

不是每篇都要把六步做重。退出条件一旦满足就继续。

---

# 1. CAPTURE — 先留住，不加工

## 目标

把稍纵即逝的注意、好奇、违和、经历和问题留下来。

合法输入包括：

- 一个刚学到的概念；
- 一句话；
- 一点感觉；
- 工作 / 学习里的奇怪现象；
- 别人的评论；
- 一个已经很清楚的问题。

最小记录：

```text
原话 / Seed：
来源：学习 / 工作 / 对话 / 自己 / 用户 / 平台
```

如果顺手能写“为什么停了一下”，就写；写不出来没关系。

## 禁止

- Capture 时立刻做综合调研；
- 逼自己写核心问题；
- 因为刚学某个模型就强行造选题。

## 退出条件

**30 秒内把东西留住。**

---

# 2. CRYSTALLIZE — 从模糊材料长出一个可继续的对象

这一步包括可选的 Incubate 和正式 Frame。

## 2.1 Seed 还很模糊：Incubate

调用 [`progressive-elaboration`](../../progressive-elaboration/)。

AI 默认循环：

```text
接住 → 展开 → 连接 → 轻问
```

规则：

- 一次最多问 1 个高信息价值问题；
- 优先具体例子、A/B 对比、某次真实经历；
- 用户说“不知道 / 脑子空白”时，给 2~3 个具体方向让其反应；
- AI 的连接只是候选，不冒充用户观点；
- 不急着 Research，也不急着写文章；
- 不要求每个 Seed 最后都变成内容。

详细创作版协议见 [`INCUBATION.md`](./INCUBATION.md)。

## 2.2 出现形状：Crystallize

当出现 2~3 个信号即可结晶：

- 一个反复出现的张力；
- 一个具体 Case；
- 用户明显认可 / 修正的一句话；
- 一个可解释机制；
- 一个外部读者也可能遇到的问题；
- 用户说“这个可以写 / 帮我整理”。

AI 做一次轻量结晶：

```text
真正主题：
核心张力：
候选真问题：
候选核心判断（如有）：
已有真实案例：
AI 候选但尚未确认：
需要外部查证：
只有用户能补充：
```

## 2.3 Frame

如果要继续研究 / 写作，把它压成一个当前可工作的真问题。

不追求“终极问题”，只要求：

- 一篇内容能处理；
- 没偷偷预设答案；
- 有可观察现象或真实语境；
- 能知道什么未知最可能改变方向。

对非平凡题，`thinking-router` 可在后台快速建立：

```text
目标 / 价值
时间尺度
硬约束
状态与反馈
关键未知
主要失败方式
```

只使用会改变题目的字段。

## 退出条件

满足任一：

- 已形成一个值得继续的问题；
- 已形成一个值得验证的候选判断；
- 已确认这只是 Seed，暂时不继续。

---

# 3. THINK — 先形成竞争解释，再决定研究多少

这一步把“思考”和“调研”放在同一个阶段，但职责必须分开。

## 3.1 Thinking Router

调用 [`thinking-router`](../../thinking-router/)。

用户不需要报模型名。

AI 应：

1. 先判断当前真正要解释 / 选择 / 预测什么；
2. 选 **1 个主工具**；
3. 至多加入 **3 个**承担不同工位的补充 / 反证工具；
4. 如果某模型删除后判断和行动不变，删掉；
5. 至少保留一个竞争解释或异质反证机会。

后台可以使用效果推理、非遍历性、ICAP、古德哈特、Wardley Map、目标函数等模型；前台不需要为了展示知识把模型名全部写出来。

## 3.2 先有竞争解释

重要问题至少保留：

```text
H1：最直接 / 常见解释
H2：当前更有解释力的候选
H3：更简单或机制不同的竞争解释
```

不是每次必须显示 H1/H2/H3，但系统不能只围绕一个喜欢的故事搜证据。

## 3.3 决定 Research 强度

### Light

适合：

- 个人观察；
- 低风险观点；
- 已有成熟知识；
- 不依赖强外部事实。

可以不单独调研。

### Standard

调用 [`research`](../../research/)。

适合：

- 科学 / 学习理论；
- 因果机制；
- 市场 / 技术 / 当前事实；
- 准备写“研究表明”“通常”“更有效”等说法。

### Deep / Audit

再调用 [`evidence-audit`](../../evidence-audit/)。

适合：

- 争议较大；
- 关键数字 / 因果链很多；
- 准备形成长期方法或高可信长文。

固定纪律：

> **模型生成问题、结构和假说；证据裁决事实上是否成立。**

## 3.4 只查会改变判断的东西

每轮问：

> **哪个未知如果查清楚，最可能改变当前判断？**

如果新增资料只是继续支持已经知道的东西，停止。

## 退出条件

能说清：

- 当前最可信解释；
- 最大竞争解释；
- 最关键证据 / 事实；
- 最大边界 / 反例；
- 仍然不知道什么。

---

# 4. JUDGE — 形成当前可承担判断，再主动攻击

这一步包含 Judge + Red Team。

## 4.1 判断不是“绝对正确”

目标是：

> **形成一个在当前证据、价值和语境下可以公开承担、又愿意被现实修正的判断。**

AI 可以从多轮对话中提炼候选判断，不要求用户面对空白页从零写句子。

真正要确认：

```text
这是我当前认可的判断：
最关键依据：
主要边界：
什么证据会让我改变判断：
```

判断所有权的标准：

- 用户理解；
- 用户认可；
- 用户可以纠正；
- 用户能脱离稿件解释主线；
- 用户愿意承担公开表达的强度。

## 4.2 Red Team

在进入写作前做一次最强善意攻击。

重点检查：

- 有没有更简单解释？
- 有没有选择 / 幸存者偏差？
- 有没有把相关写成因果？
- 有没有忽略参考类 / 基准率？
- 有没有把平均收益用于一个可能被毁掉的个体路径？
- 有没有古德哈特 / 代理指标问题？
- 有没有二阶反应和适应性行为？
- 有没有把个人经验外推成普遍规律？
- 模型是不是一个好故事，但证据不够？
- 结论是不是比证据更强？

如果主工具已明确，优先用不同类型的工具攻击它。

## 退出条件

- 判断经攻击后仍成立；或
- 已降级到证据真正支持的强度；或
- 发现题立错，返回 CRYSTALLIZE / THINK。

---

# 5. CREATE — 从已有理解写，不从空白页重来

这一步包含 Draft → Adapt → Publish。

## 5.1 用户说“整理成文章”

这是明确触发器。

AI 不重新让用户填问题卡，而把前面的对话、研究、判断直接作为材料。

先内部做 Article Brief：

```text
真正主题
用户已认可的核心判断
关键推理链
用户自己的案例 / 原话 / 转折
AI 提出但尚未确认
需要外部查证
只有用户能补充
```

然后 Gap Check：

- 外部事实 / 论文 / 定义 / 数据 → AI 自己 Research；
- 只有用户本人知道且会改变文章 → 问 1~3 个具体问题；
- 只影响小细节 → 保守处理 / 删除 / 标明不确定。

## 5.2 母稿

母稿是 canonical source，不先讨好平台。

默认逻辑可以是：

```text
真实现象 / 经历
→ 为什么困惑
→ 常见解释
→ 为什么不够
→ 更好的机制 / 判断
→ 证据与案例
→ 边界 / 反例
→ 读者能带走什么
```

不要求机械使用八段式。

写作纪律：

- 一篇只打一颗钉子；
- 案例优先于概念；
- 机制优先于术语；
- 尽量保留用户真实表达和思路演化；
- 删除正确但不服务主线的内容；
- 不制造假共识、假金句和宏大升华；
- 后台使用过的模型不等于全部写进文章。

如果材料只够 L1 / L2，就不硬凑 L3 长文。

## 5.3 Adapt

先有母稿，再适配平台。

平台只改变：

1. 入口；
2. 信息密度；
3. 媒介 / 节奏。

事实边界、核心判断、必要限制条件不能变宽。

前 10 次：**只要求 1 个主平台，最多 1 个副平台。**

## 5.4 Publish

发布前只检查：

- 核心判断清楚吗？
- 有没有明显事实错误？
- 有没有把推断写成事实？
- 标题有没有超过正文能支持的强度？
- 有没有为了完整塞入第二个核心观点？

然后发布。

## 退出条件

**真实发布，而不是停在 80% 草稿。**

---

# 6. LEARN — 让现实回到系统

24~72 小时后不需要豪华复盘。

至少记录一个：

```text
新的反应 / 评论 / 私信 / Case：
它攻击的是传播，还是核心判断？
有没有新 Seed / 新问题？
我的判断是否需要更新？
```

## 区分四种失败

```text
入口失败       没人停下来
表达失败       人看了但没理解
传播失败       内容本身好但分发弱
观点 / 模型失败 现实反馈真正攻击了核心判断
```

不要因为数据差就推翻观点，也不要因为数据高就证明观点正确。

## Thinking Learn

如果一个思维模型在真实 Case 中真的改变过判断，再考虑写回 Personal Model Card：

```text
触发信号：
它改变了什么：
最强竞争 / 反证工具：
新边界 / 误用：
真实 Case：
```

不预先建立 100 个模型卡。

## 退出条件

本轮至少得到一个：

- 新 Seed / 新问题；
- 一个反例 / Case；
- 一次判断更新；
- 一个流程摩擦；
- 一个值得内化的模型触发器。

然后关闭这一轮。

---

# 特殊触发器

## “我不知道问什么”

→ 回到 `progressive-elaboration`，降低认知负荷。

## “帮我整理刚才聊的”

→ 直接 Crystallize / Article Brief，不让用户重填流程。

## “帮我查一下这个说法靠谱吗”

→ 进入 THINK / Research，不先写文章。

## “这个判断我基本有了，帮我严格检查”

→ 直接 JUDGE / Red Team。

## “这篇写好了，改成小红书 / 视频号”

→ 直接 CREATE / Adapt，不重新研究，除非发现事实问题。

---

# V0.3 摩擦预算

这些不是 KPI，只用于发现流程过重：

```text
Capture：< 30 秒
Crystallize：普通 Seed 不强制时限；明确结晶动作 < 10 分钟
Frame：< 15 分钟
普通 Research：30~90 分钟
Judge + Red Team：< 30 分钟
Draft：60~120 分钟
Adapt：< 母稿耗时 30%
Review：< 15 分钟
```

如果系统导致更不想开始：**先删步骤，不加功能。**

如果连续多个 Case 暴露同一摩擦，再更新系统。不要一篇一改。
