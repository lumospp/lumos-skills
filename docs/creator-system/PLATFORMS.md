# Platforms — 平台是不同表达界面，不是四套创作系统

## 1. 总原则

不要把“全平台运营”当成 V0.1 的目标。

推荐结构：

```text
一个问题
  ↓
一个母稿 / 一个核心判断
  ↓
一个主平台发布
  ↓
如果适合，再顺手适配第二个平台
```

前 10 次创作，一次最多 2 个平台。

---

## 2. 各平台在系统里的角色

### 小红书 — 问题入口 / 认知冲突测试

适合：

- 很具体的日常困惑；
- “明明 X，却 Y”的反常现象；
- 一个模型解释一个问题；
- 可视觉化为 5~10 个信息块的内容。

不要：

- 把 3000 字文章硬拆成 12 张图；
- 每页都塞满字；
- 为了种草感制造不存在的个人经历。

推荐母结构：

```text
封面：具体冲突
第1屏：真实场景
第2屏：通常解释
第3~5屏：更好的机制
第6屏：边界/反例
最后：一个可带走的行动或问题
```

---

### 视频号 — 口头思考 / 信任建立

适合：

- 一个观点可以用嘴讲清；
- 有现实故事或案例；
- 需要语气和人格来增强理解。

推荐：

```text
前 5~10 秒：直接说冲突
中间：只走一条逻辑线
结尾：给一个新的看法/行动
```

不要把文章逐字朗读。

如果自己无法不看稿讲出主线，说明还没有真正内化。

---

### 公众号 — Canonical Essay / 长期知识资产

适合：

- 一个问题值得更完整论证；
- 有证据、竞争解释、边界；
- 三个月以后仍值得读。

公众号优先承担：

> **当前这个问题最完整、最可辩护的公开版本。**

不要因为“公众号应该长”而拉长。

---

### X / 微博 — 观点原子 / 问题探针

适合：

- 100~500 字 insight atom；
- 一个尚未成熟的问题；
- 一个局部反常识；
- 对已有内容做二次切片。

它们可以承担类似公开 R&D 的作用：

```text
想法 → 发出去 → 看反驳/共鸣 → 更新 → 再长成文章
```

不要把它们变成必须每日打卡的内容 KPI。

---

### 知乎 — 问题库 / 长答案验证场

优先作为：

- 发现真实问题的来源；
- 查看大众当前解释；
- 在高度匹配的问题下发布已有母稿的回答版本。

不要为了知乎单独制造完全不同的研究流程。

---

### GitHub — 方法与可复用资产

GitHub 不承担日常内容发布。

适合沉淀：

- Creator System；
- 研究 Skill；
- Prompt；
- 公开模板；
- 可复用方法；
- 经过实践的工具。

---

## 3. 平台选择规则

完成母稿后只问：

> **这个问题，最自然的表达媒介是什么？**

- 需要完整论证 → 公众号
- 需要快速验证冲突是否共鸣 → 小红书
- 需要人物语气、口头故事 → 视频号
- 只有一个观点原子 → X/微博
- 恰好已有高匹配提问 → 知乎

不是：

> 哪个平台最近流量最好？

流量是二级变量，表达匹配优先。

---

## 4. V0.1 建议

目前优先：

```text
主输出：小红书 或 公众号（二选一）
辅助：视频号 / X / 微博按内容顺手适配
```

一个现实可执行节奏示例：

```text
问题原子 → 小红书验证
如果值得深入 → 公众号母稿
如果适合口头表达 → 再录视频号
```

也允许反过来：先写公众号，再拆小红书。

关键是**不设硬性全平台流水线**。
