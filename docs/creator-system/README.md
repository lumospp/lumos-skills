# Lumos Creator System V0.2

> 一个问题驱动、证据优先、AI 增强但不替代判断，并通过真实 Case 持续内化思维工具的个人创作系统。
>
> 当前状态：**实验版，先真实使用，再决定哪些部分继续固化为 Skill。**

## 1. 这个系统解决什么

不是解决“如何批量生产内容”，而是解决：

> **如何把真实生活、学习、工作中的观察、概念、经历、问题和模糊念头，经过对话、研究、判断和表达，变成有用的公开内容，并让现实反馈继续改善自己的世界模型。**

创作最终是问题驱动，但**不要求一开始就有一个好问题**。

真实创作有两种入口：

```text
Problem-first
清楚问题 → Frame → Research → Judge → ...

Seed-first
概念 / 感受 / 片段 / 半成品念头
        ↓
对话孵化 Incubate（可选）
        ↓
结晶 Crystallize
        ↓
Select / Frame → Research → Judge → ...
```

完整闭环：

```text
真实世界 / 学习 / 工作 / 评论 / 社会讨论
                    ↓
           Seed / Observation / Question
                    ↓
          [可选] 对话孵化 / 结晶
                    ↓
              压成一个真问题
                    ↓
        思维路由 + 调研 + 竞争解释
                    ↓
                人形成判断
                    ↓
             Red Team / 反证
                    ↓
                 母稿
                    ↓
            按平台重新表达
                    ↓
                 发布
                    ↓
     评论 / 数据 / Case / 行动结果
                    ↓
        更新世界模型与 Model Card
                    ↓
                 新种子 / 新问题
```

## 2. V0.2 的四层架构

Creator System 不把 Skill 机械串成流水线，而是让不同能力承担不同工位：

```text
                 Creator System
                流程 / 状态控制层
                       │
          ┌────────────┼────────────┐
          │            │            │
          ▼            ▼            ▼
     Thinking       Evidence     Expression
      Engine         Engine        Engine
          │            │            │
 Modern Thinking   research /    Editor /
     Tools        evidence-audit  Adapter
          │            │            │
          └─────┬──────┘            │
                ▼                   │
             Human Judge ───────────┘
                │
                ▼
              Reality
                │
                ▼
        Knowledge Base / Model Cards
                │
                └────────→ 下一轮
```

### Creator System

负责“认知如何流动”：Capture → [Incubate] → Select → Frame → Research → Judge → Red Team → Draft → Publish → Learn。

`Incubate` 是可选层，只在输入还模糊时启用。

### Modern Thinking Tools

负责“这一刻该怎么想”：先建立最小问题地图，再自动选择 1 个主工具和至多 3 个补充/反证工具，帮助改变问题表示、解释机制、评估权衡、设计行动和更新条件。

它是默认 **Reasoning Engine**，不是新的 Agent，也不在模糊 Seed 阶段强行全面启动。

### Research / Evidence Audit

负责“事实上是什么”：核验事实、研究、数据、参考类、反例和证据边界。

固定纪律：

> **模型生成假说，证据裁决假说。**

### 人

保留最终判断、价值权衡、风险承担和公开主张的所有权。

注意：

> **判断所有权 ≠ 必须面对空白页独自写出核心判断。**

AI 可以从多轮对话中提炼候选判断；人负责理解、确认、纠正、解释和承担。

### 现实

拥有最终裁决权。评论、真实 Case、实验和行动结果都可以迫使系统更新。

## 3. V0.2 的核心原则

1. **允许弱输入**：一个概念、一句话、一点感觉也能启动，不要求先想出好问题。
2. **问题驱动，不是知识目录驱动**：问题可以在对话中生长，但不能为了刚学的概念硬造现实问题。
3. **对话可以生成问题**：当用户脑子空白时，AI 应降低负担，通过接住、展开、连接和轻问帮助想法结晶。
4. **模型服务于解释与判断**：ICAP、奈特不确定性、古德哈特等是工具，不是选题。
5. **重要模型要真正用起来**：经过筛选的高质量思维工具不是收藏品，应在真实问题中被自动路由、反复使用和检验。
6. **一次 1 个主工具，少量补充/反证**：工具必须改变问题表示、判断标准或行动；否则只是标签。
7. **模型不能冒充证据**：思维工具决定“怎样看”，证据决定“事实上是什么”。
8. **后台复杂，前台简单**：可以调用多个后台能力，但一篇只打一颗钉子；读者不需要看到所有模型名。
9. **AI 是对话伙伴、研究伙伴、思维路由器和对手，不是作者替身**。
10. **母稿优先于多平台**：先形成一个可独立成立的内容母体，再适配平台。
11. **发布是实验，不是交卷**：反馈用于更新判断，而不是只判断“爆没爆”。
12. **课程 / Skill 是高质量起点，不是圣经**：保留来源定义，同时允许真实 Case 形成自己的触发器、边界、反例和理解。
13. **长期目标是内化，不是永久依赖 Router**：高频重要工具应逐渐从“AI 提醒”变成自己能在现实中 pass@1 调用。
14. **先跑起来，再自动化**：系统修改必须由真实 Case 暴露的问题触发。

## 4. 两条最小使用路径

### 路径 A：我已经有问题

```text
1. 写下真实现象 / 问题
2. Frame
3. AI 生成竞争解释、选择必要思维工具、找关键未知
4. Light / Standard / Deep 调研
5. Judge + Red Team
6. 形成母稿
7. 发布
8. 用现实反馈更新
```

### 路径 B：我只有一点想法

```text
1. 丢给 AI 一个 Seed
2. AI 不逼问“你的核心问题是什么”
3. 通过对话：接住 → 展开 → 连接 → 一次轻问一个点
4. 材料长出来后，AI 主动做 Crystallize
5. 从对话中提炼候选问题 / 候选判断，让我确认或修正
6. 需要外部事实时 AI 自己 Research；只有我知道的信息再问我
7. 材料够就整理成母稿；不够则降级成 Insight Atom 或继续孵化
8. 发布并反馈
```

详细协议见 [`INCUBATION.md`](./INCUBATION.md)。

**仍然禁止：**

- 搭自动抓热点系统；
- 先整理完整 100 个模型卡；
- 每篇强行调用多个模型；
- 建复杂数据库；
- 把对话变成一连串开放式采访题；
- 同时发 4 个平台；
- 先把全部 Prompt 优化完才开始；
- 因为资料还可以继续查而无限延迟发布。

## 5. 输入与输出

### 输入

系统允许六类输入：

- `SEED`：尚未形成问题的一点想法、感受、连接或半成品念头。
- `OBSERVATION`：真实观察，例如“AI 明明讲得很清楚，但过两天我还是不会”。
- `QUESTION`：别人真实问的问题、评论区问题、自己的困惑。
- `EXPERIENCE`：自己正在做的项目、踩坑、实验结果。
- `CONCEPT`：刚学到的模型或概念；可以先孵化，不要求立刻找现实问题。
- `SIGNAL`：知乎、小红书、微博、X、新闻等出现的讨论信号。

### 输出

不要求每次都写长文。允许以下输出层级：

```text
L-1 Seed / Connection  一个还没长成问题的种子或连接
L0 Problem Note        一个值得研究的问题
L1 Insight Atom        100~500 字观点原子
L2 Short Content       小红书 / 微博 / X / 短视频口播
L3 Canonical Essay     公众号 / 长文母稿
L4 Reusable Asset      方法、模板、Prompt、Skill、产品洞见、成熟 Model Card
```

很多 Seed 最后不变成文章也完全正常。

## 6. AI 在系统里的位置

AI 可以承担：

- 接住并扩展模糊种子；
- 从多轮对话中发现张力、连接和候选问题；
- 从用户表达中提炼候选核心判断；
- 问题澄清；
- 自动选择候选思维工具；
- 搜索真实讨论与证据；
- 提出竞争解释；
- 查反例；
- 建 Claim → Evidence；
- Judge / Red Team；
- 结构整理；
- 表达压缩；
- 平台适配；
- 发布后的评论聚类与复盘。

AI 不应该替你承担：

- 什么最终值得你关心；
- 你是否真正认可一个判断；
- 你愿意为哪个观点负责；
- 课程模型与个人经验冲突时，你最终如何权衡；
- 自己真实经历了什么。

一句话：

> **AI 降低空白页压力、扩展研究与推理带宽；人保留理解、判断、价值与责任；现实保留最终否决权。**

## 7. 思维工具如何逐渐变成自己的

不要先背完或整理完 100 个模型。

```text
真实问题 / 对话中长出的问题
  ↓
AI Router 选出工具
  ↓
工具真实改变判断 / 行动
  ↓
现实反馈验证或修正
  ↓
写回 Personal Model Card
  ↓
形成自己的触发器 / 边界 / 案例
  ↓
以后更容易自己自动调用
```

Model Card 建议分成：

- **Source Layer**：忠实保存课程 / 原始来源；
- **Personal Layer**：自己的理解、真实触发器、误用、反例、Problem ID 和判断变化。

## 9. V0.2 的成功标准

不是粉丝，不是点赞，不是用了多少模型，也不是“系统搭好了”。

前 10 次运行重点检查：

- 一个很模糊的 Seed 是否也能低压力启动；
- AI 是否减少了“我必须先想出好问题”的负担；
- 用户说“不知道”时，AI 是否会给具体支架而不是继续拷问；
- 最终形成的判断是否真的是用户理解并认可的，而非 AI 单方面生成；
- 是否不再需要用户手动告诉 AI 应该用哪个模型；
- 主工具是否真的改变了问题表示、判断或行动；
- 是否把模型和证据分开；
- 是否成功发布；
- 发布后是否得到新问题、新证据、真实 Case 或判断更新；
- 整个流程有没有重到不想开始。

如果一个环节连续 3 次让你卡住，优先删除或简化，而不是增加新的工具。

最终目标不是建立一套越来越复杂的创作机器，而是：

> **让真实好奇驱动对话，让对话长出问题，让高质量思维工具帮助形成判断，让现实持续修正这些判断，并把能力逐渐内化到人身上。**
