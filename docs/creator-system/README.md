# Lumos Creator System V0.2

> 一个问题驱动、证据优先、AI 增强但不替代判断，并通过真实 Case 持续内化思维工具的个人创作系统。
>
> 当前状态：**实验版，先真实使用，再决定哪些部分继续固化为 Skill。**

## 1. 这个系统解决什么

不是解决“如何批量生产内容”，而是解决：

> **如何把真实生活、学习、工作中值得想清楚的问题，经过研究、判断和表达，变成有用的公开内容，并让现实反馈继续改善自己的世界模型。**

创作不是终点，而是一个公开思考闭环：

```text
真实世界 / 学习 / 工作 / 评论 / 社会讨论
                    ↓
                发现问题
                    ↓
            找冲突 / 异常 / 困惑
                    ↓
              压成一个真问题
                    ↓
        思维路由 + 调研 + 竞争解释
                    ↓
                人形成判断
                    ↓
             Red Team / 反证
                    ↓
                 母稿
                    ↓
            按平台重新表达
                    ↓
                 发布
                    ↓
     评论 / 数据 / Case / 行动结果
                    ↓
        更新世界模型与 Model Card
                    ↓
                 新问题
```

## 2. V0.2 的四层架构

Creator System 不把 Skill 机械串成流水线，而是让不同能力承担不同工位：

```text
                 Creator System
                流程 / 状态控制层
                       │
          ┌────────────┼────────────┐
          │            │            │
          ▼            ▼            ▼
     Thinking       Evidence     Expression
      Engine         Engine        Engine
          │            │            │
 Modern Thinking   research /    Editor /
     Tools        evidence-audit  Adapter
          │            │            │
          └─────┬──────┘            │
                ▼                   │
             Human Judge ───────────┘
                │
                ▼
              Reality
                │
                ▼
        Knowledge Base / Model Cards
                │
                └────────→ 下一轮
```

### Creator System

负责“认知如何流动”：Capture → Select → Frame → Research → Judge → Red Team → Draft → Publish → Learn。

### Modern Thinking Tools

负责“这一刻该怎么想”：先建立最小问题地图，再自动选择 1 个主工具和至多 3 个补充/反证工具，帮助改变问题表示、解释机制、评估权衡、设计行动和更新条件。

它是默认 **Reasoning Engine**，不是新的第七个 Agent。

### Research / Evidence Audit

负责“事实上是什么”：核验事实、研究、数据、参考类、反例和证据边界。

固定纪律：

> **模型生成假说，证据裁决假说。**

### 人

保留最终判断、价值权衡、风险承担和公开主张的所有权。

### 现实

拥有最终裁决权。评论、真实 Case、实验和行动结果都可以迫使系统更新。

## 3. V0.2 的核心原则

1. **问题驱动，不是知识目录驱动**：不因为今天学了一个概念，就强行写这个概念。
2. **找异常，不追热点本身**：热点只用于发现长期问题；优先找“为什么明明 X，却 Y？”的认知冲突。
3. **模型服务于解释与判断**：ICAP、奈特不确定性、古德哈特等是工具，不是选题。
4. **重要模型要真正用起来**：经过筛选的高质量思维工具不是收藏品，应在真实问题中被自动路由、反复使用和检验。
5. **一次 1 个主工具，少量补充/反证**：工具必须改变问题表示、判断标准或行动；否则只是标签。
6. **模型不能冒充证据**：思维工具决定“怎样看”，证据决定“事实上是什么”。
7. **后台复杂，前台简单**：可以调用多个后台能力，但一篇只打一颗钉子；读者不需要看到所有模型名。
8. **一个内容只有一个核心判断**：其他内容只能作为证据、机制、反例、边界或行动建议。
9. **AI 是研究伙伴、思维路由器和对手，不是作者替身**：AI 可搜索、反驳、整理、改写；核心判断必须由人承担。
10. **母稿优先于多平台**：先形成一个可独立成立的内容母体，再适配平台，不为每个平台重新研究一次。
11. **发布是实验，不是交卷**：反馈用于更新判断，而不是只用于判断“爆没爆”。
12. **课程 / Skill 是高质量起点，不是圣经**：保留来源定义，同时允许真实 Case 形成自己的触发器、边界、反例和理解。
13. **长期目标是内化，不是永久依赖 Router**：高频重要工具应逐渐从“AI 提醒”变成自己能在现实中 pass@1 调用。
14. **先跑起来，再自动化**：系统修改必须由真实 Case 暴露的问题触发，禁止为了工作流本身投入大量部署时间。

## 4. 最小使用路径

普通创作只需要：

```text
1. 写下一个最近让你觉得“奇怪”的现象
2. 把它改写成一个具体问题
3. AI 自动生成竞争解释、选择必要思维工具，并找最关键未知
4. 根据问题强度做 Light / Standard / Deep 调研
5. 自己形成一句核心判断
6. 让 AI 做 Judge + Red Team，修正到证据真正支持的强度
7. 让 AI 帮你组织母稿，你再修改
8. 只选 1 个平台发布
9. 用评论 / Case / 行动结果更新判断和模型理解
```

**仍然禁止：**

- 搭自动抓热点系统；
- 先整理完整 100 个模型卡；
- 每篇强行调用多个模型；
- 建复杂数据库；
- 同时发 4 个平台；
- 为了写作研究新软件；
- 先把全部 Prompt 优化完才开始；
- 因为资料还可以继续查而无限延迟发布。

## 5. 输入与输出

### 输入

系统允许五类输入：

- `OBSERVATION`：真实观察，例如“AI 明明讲得很清楚，但过两天我还是不会”。
- `QUESTION`：别人真实问的问题、评论区问题、自己的困惑。
- `EXPERIENCE`：自己正在做的项目、踩坑、实验结果。
- `CONCEPT`：刚学到的模型或概念，但必须继续寻找它能解释的真实问题，并允许竞争模型胜出。
- `SIGNAL`：知乎、小红书、微博、X、新闻等出现的讨论信号。

### 输出

不要求每次都写长文。允许以下输出层级：

```text
L0 Problem Note      一个值得研究的问题
L1 Insight Atom      100~500 字观点原子
L2 Short Content     小红书 / 微博 / X / 短视频口播
L3 Canonical Essay   公众号 / 长文母稿
L4 Reusable Asset    方法、模板、Prompt、Skill、产品洞见、成熟 Model Card
```

大多数问题停在 L1/L2 完全正常。不要强迫每个问题都长成 3000 字文章。

## 6. AI 在系统里的位置

AI 可以承担：

- 问题澄清；
- 自动选择候选思维工具；
- 搜索真实讨论与证据；
- 提出竞争解释；
- 查反例；
- 建 Claim → Evidence；
- Judge / Red Team；
- 结构整理；
- 表达压缩；
- 平台适配；
- 发布后的评论聚类与复盘；
- 提醒哪些真实 Case 值得写回 Model Card。

AI 不应该替你承担：

- 这个问题是否真的值得你写；
- 你最终相信哪个解释；
- 你愿意为哪个观点负责；
- 什么与你的长期视角有关；
- 是否为了传播牺牲事实边界；
- 课程模型与个人经验冲突时，你最终如何权衡并承担判断。

一句话：

> **AI 扩展研究、推理和表达带宽，人保留问题选择、判断、价值与责任；现实保留最终否决权。**

## 7. 思维工具如何逐渐变成自己的

不要先背完或整理完 100 个模型。

正确路径是：

```text
真实问题
  ↓
AI Router 选出工具
  ↓
工具真实改变判断 / 行动
  ↓
现实反馈验证或修正
  ↓
写回 Personal Model Card
  ↓
形成自己的触发器 / 边界 / 案例
  ↓
以后更容易自己自动调用
```

Model Card 建议分成：

- **Source Layer**：忠实保存课程 / 原始来源；
- **Personal Layer**：自己的理解、真实触发器、误用、反例、Problem ID 和判断变化。

这样既避免把原理论随意改坏，也避免永远停留在“别人的知识”。

## 9. V0.2 的成功标准

不是粉丝，不是点赞，不是用了多少模型，也不是“系统搭好了”。

前 10 次运行重点检查：

- 是否真的从现实问题出发；
- 是否不再需要用户手动告诉 AI 应该用哪个模型；
- 主工具是否真的改变了问题表示、判断或行动；
- 是否形成了自己的判断，而非 AI 拼接；
- 是否至少找过一个竞争解释或异质反证；
- 是否把模型和证据分开；
- 是否成功发布；
- 发布后是否得到新问题、新证据、真实 Case 或判断更新；
- 是否出现值得写回个人 Model Card 的理解；
- 整个流程有没有因为加入 Thinking Router 而重到不想开始。

如果一个环节连续 3 次让你卡住，优先删除或简化，而不是增加新的工具。

最终目标不是建立一套越来越复杂的创作机器，而是：

> **让真实问题驱动学习和创作，让高质量思维工具在真实 Case 中被反复运行，让判断接受现实反馈，并把这些能力逐渐内化成人自己的认知系统。**
